# Merchant Introduction

> Choose an x402 server integration, configure PayAI facilitation, and prepare payment, discovery and recovery behavior.

## Charge for an HTTP resource

An x402 resource server advertises payment requirements and uses a facilitator to verify and settle supported payments. Your application still owns resource delivery, pricing, access control and recovery.

If you want to pay for a resource instead, start with the [client guide](https://docs.payai.network/x402/clients/introduction.md). For a first end-to-end example, use the [quickstart](https://docs.payai.network/x402/quickstart.md).

## Understand the payment flow

![x402 sequence diagram](https://mintcdn.com/payai/2DGsVUJGFkMxMKTt/images/x402-sequence-diagram.svg?fit=max\&auto=format\&n=2DGsVUJGFkMxMKTt\&q=85\&s=750a29402143e49980393d116826ef2d)

The server challenges an unpaid request, accepts a retry carrying a payment authorization, and verifies the selected terms. Settlement and resource delivery must follow the lifecycle required by your integration. See the [x402 reference](https://docs.payai.network/x402/reference.md) for wire formats and the [facilitator introduction](https://docs.payai.network/x402/facilitators/introduction.md) for PayAI's role.

HTTP compatibility alone is not payment compatibility: both ends must support the selected network, token and scheme. Check [supported networks](https://docs.payai.network/x402/supported-networks.md). Fee sponsorship depends on the payment flow, and end-to-end latency depends on application work, transport and settlement; neither zero network costs nor sub-second settlement is universal.

## Start paid work safely

For costly `exact` requests, confirm settlement before inference or streaming.
Verification alone does not reserve funds. Funded channels reserve capacity before
work and redeem vouchers afterward. Follow the [payment safety guide](https://docs.payai.network/x402/servers/payment-safety.md)
for expiry checks, payment ordering and pending-payment recovery.

## Configure PayAI and prepare production

1. Follow your framework guide's PayAI facilitator configuration. Review [pricing](https://docs.payai.network/x402/facilitators/pricing.md): you start with 1,000 free credits, and ordinary exact payments can serve mainnet production traffic without an API key until they run out.
2. For paid usage or an assigned lane, keep facilitator credentials on the server. An autonomous agent can [buy credits and receive a key over x402](https://docs.payai.network/x402/facilitators/agent-api-keys.md) with no portal signup; the paying wallet gets a wallet-owned agent account programmatically. The [merchant dashboard](https://merchant.payai.network) is the optional human-managed route. See [facilitator authentication](https://docs.payai.network/x402/facilitators/authentication.md) for package-based and direct HTTP setup.
3. Configure [Bazaar discovery](https://docs.payai.network/x402/facilitators/bazaar.md) if you want to expose supported discovery metadata. Serving an HTTP endpoint alone does not list it automatically.
4. For variable charges, follow the [dynamic pricing guide](https://docs.payai.network/guides/dynamic-pricing-x402.md) and validate that the payment authorization covers the accepted terms.
5. Plan for capacity limits, timeouts and uncertain outcomes using the [capacity and recovery guidance](https://docs.payai.network/x402/facilitators/capacity-and-limits.md). A request timeout does not establish that settlement failed.
