Search query (brand name or keyword)
query
Optional
#query
Free-text search on trademark NAME. Examples: 'apple', 'louis vuitton', 'tesla', 'volkswagen'. Provide this, 'applicantName', or a filing/registration number — at least one is required.
Type: string
Applicant / owner name
applicantName
Optional
#applicantName
Search by the APPLICANT / owner name — returns every trademark owned by that entity. Examples: ['APPLE INC'], ['NIKE'], ['LVMH']. Matches the owner-name text (so 'APPLE INC' also catches historical variants like 'APPLE COMPUTER, INC.'). Multiple names = OR. Can be combined with 'query' (mark name) to AND. Provide this, 'query', or a filing/registration number.
Type: string[]

Application / filing numbers
applicationNumbers
Optional
#applicationNumbers
Look up trademarks directly by APPLICATION (filing) number — exact match, as shown by the office. Examples: ['018000001'] (EUIPO), ['73202097'] (USPTO serial). One or many numbers (a pasted comma/newline-separated list works too). The same number can exist at several offices, so add 'offices' (e.g. ['EM']) for a unique hit. If a zero-padded number returns nothing, the actor retries it without leading zeros. Can be used alone or combined with any other filter.
Type: string[]
Default:
[ ]

Fuzzy search
fuzzySearch

#fuzzySearch
Enable approximate / phonetic matching (same as the 'Fuzzy search' toggle in the TMview UI). Enrich with full details (goods & services, registration/expiry dates)
enrichDetails
Optional
#enrichDetails
When ON, fetches the full TMview detail record for EACH result: registration & expiration dates, opposition period start/end, complete goods & services descriptions per Nice class, detailed applicant info (address, nationality), legal representatives, and renewal history. Detail requests run concurrently. Adds one request per result and is billed separately as a 'trademark-detail' event. Leave OFF for fast, cheap name/status/Nice-class search.
Type: boolean
Default: false
Resolve applicant → company record (portfolio link)
enrichApplicant
Optional
#enrichApplicant
When ON, resolves each mark's applicant to a real company. French applicants are matched live to their SIREN + size + sector + active/ceased status via the official register (same source as our pappers-sirene-scraper); applicants from 30+ other countries get a pointer to the matching national company-registry actor. Turns trademark data into brand-owner intelligence (lead-gen, competitive mapping, IP due diligence). Billed as 'applicant-enriched' only for applicants successfully resolved to a company record. Best combined with enrichDetails (which provides the applicant's country).
Type: boolean
Default: false
Reference mark (for brand-clearance scoring)
referenceMark
Optional
#referenceMark
The proposed brand name you want to CLEAR. When set, every result is scored against it for free: Jaro-Winkler name similarity, phonetic match (Metaphone/Soundex) and Nice-class overlap → a 0-100 computed_conflict_score with a band (high/medium/low/none), written into each record's 'clearance' object. Leave empty to skip clearance scoring. Defaults to 'query' when analyzeClearance is ON.
Type: string | null

#referenceNiceClasses
The Nice classes (1-45) your proposed mark would be used in. Sharpens the clearance conflict score (a name clash only matters where the goods/services overlap). Provide as strings, e.g. ['9','42']. Optional.

AI likelihood-of-confusion (premium, paying plans)
analyzeClearance
Optional
#analyzeClearance
When ON, an AI model scores each existing mark against your referenceMark for likelihood of confusion the way an EU examiner would: semantic_similarity (meaning, not just spelling — catches translations/synonyms), goods_conflict (overlap of goods & services), an overall likelihood_of_confusion 0-100, a verdict (clear/caution/high_risk), a recommended_action and one-line reasoning. This is the enterprise brand-clearance feature — screening triage, not legal advice. Billed as 'clearance-analyzed' per mark scored. Requires a paid Apify plan and the account OpenRouter key. Best with enrichDetails ON (feeds the goods & services text to the model).
Type: boolean
Default: false
Reference goods & services (for AI clearance)
referenceGoods
Optional
#referenceGoods
Optional free-text description of the goods/services your proposed mark will cover (e.g. 'mobile software for fitness tracking'). Gives the AI clearance model the context to judge goods conflict. Only used when analyzeClearance is ON.
Type: string | null
Watch mode (only new/updated marks on recurring runs)
incrementalMode
Optional
#incrementalMode
When ON, remembers every trademark seen on the previous run (per stateKey) and, on the next run, tags each mark NEW / UPDATED / UNCHANGED. By default only NEW and UPDATED marks are emitted and billed — so scheduling this daily/weekly becomes a trademark-watch that surfaces competitor filings and status changes cheaply. Combine with a schedule for brand monitoring.
Type: boolean
Default: false
Include unchanged marks (watch mode)
includeUnchanged
Optional
#includeUnchanged
When incrementalMode is ON, also emit (and bill) marks that did not change since the last run. Leave OFF to receive only the delta.
Type: boolean
Default: false
Emit expired markers (watch mode)
includeExpired
Optional
#includeExpired
When incrementalMode is ON, also emit lightweight EXPIRED markers for marks that were present last run but dropped off this run. These markers are metadata and are NOT billed.
Type: boolean
Default: false
