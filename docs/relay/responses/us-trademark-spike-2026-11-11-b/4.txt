Open Data Portal Registration Requirement​
In order to access the Open Data Portal (ODP), starting on June 18, 2026 , you'll need to sign in with a valid USPTO.gov account. Please sign in using the navigation below or create an account using the button in the banner. If you want more information on this initiative, please visit our Register for ODP access page (support/universal-registration) and sign-in today. Additionally, your USPTO.gov account requires multi-factor authentication (MFA). For guidance on MFA setup, please visit the USPTO.gov account FAQs (https://www.uspto.gov/learning-and-resources/account-faqs#subcategory=&category=Multifactor+authentication) .
Also, effective August 18, 2026 , users are required to provide four additional fields of information on their USPTO profile. API keys for accounts that did not complete these fields by October 8, 2026, have been deactivated. To reactivate your key, update these fields in your USPTO.gov account (https://account.uspto.gov/profile) settings by selecting the “Open Data Portal” section at the bottom of the left navigation menu. Next login to ODP and click on the Activate API Key button on the Manage API Key page. See our FAQs (/support/faq) for details.

API rate limits
Was this page helpful?
ODP provides three types of APIs that have their own set of rate limits: Meta data retrieval APIs, Patent File Wrapper Documents API and Bulk Datasets Downloads API.
Meta data retrieval APIs:
For each data product there are a set of meta data retrievals-
Patent File Wrapper API (/apis/patent-file-wrapper/search) meta data retrieval includes Application Data (/apis/patent-file-wrapper/application-data) , Continuity (/apis/patent-file-wrapper/continuity) , Transactions (/apis/patent-file-wrapper/transactions) , Patent Term Adjustment (/apis/patent-file-wrapper/patent-term-adjustment) , Address and Attorney/Agent Information (/apis/patent-file-wrapper/address) , Assignments (/apis/patent-file-wrapper/assignments) , Foreign Priority (/apis/patent-file-wrapper/foreign-priority) and Associated Documents (/apis/patent-file-wrapper/associated-documents) .
Bulk Datasets API (/apis/bulk-data/search) meta data retrieval includes Product Data (/apis/bulk-data/product) .
Final Petition Decisions API (/apis/petition-decision/search) meta data retrieval includes Search (/apis/petition-decision/search) , Document Data (/apis/petition-decision/petition-decision-data) , and Download (/apis/petition-decision/download) .
Meta data retrievals are limited to 5 million calls per week for all the APIs in this category combined.
Patent File Wrapper’s Documents API:
The weekly limit for all the APIs under the Patent File Wrapper Documents API (/apis/patent-file-wrapper/documents) is 1,200,000. This means you can make 1.2 million calls per week for the APIs under this category.
Bulk Datasets’ Downloads API:
For the same file downloaded using the Bulk Datasets Downloads API (/apis/bulk-data/download) , you are limited to 20 downloads per year using your API key, except for XML files which has a much higher limit
You can download up to 5 files per 10 seconds from the same IP address.
Our files are redirected and digitally signed with a signature expiring in 5 seconds, so be sure to start downloading any redirected files right way.
API rate limit reset
Your weekly quota for Meta data retrieval and Patent File Wrapper Documents APIs will reset on Sunday at midnight Greenwich Time (also known as UTC). After the reset, you will be able to use a full allocated quota again.
We limit all API calls to one API call per API key. You will need to wait until an API call completed until starting a new one. We also advise against using the same API key in applications running in parallel: concurrent API calls with the same key are currently blocked.
API request threshold
Burst: This defines how many requests can be run in parallel per API Key. It is set to 1, meaning you should not run any requests in parallel at all for the same API key.
Rate: This defines how many requests one can submit per second. It is set at 4 to 15, depending on the API call type. For example, if an API call takes 0.1 seconds, you can still submit 10 sequential calls even with the burst limit of 1.
In general, you should design a system that waits for an API call to finish before making the next call using the same API key, as some of the calls require significant resources.
If you submit more than one request at a time or exceed weekly quota, you will get the error message: “ HTTP 429 Too Many Requests. ” Therefore, it is “best practice” to handle an HTTP 429 error gracefully. We strongly discourage automatic retries, without at least 5 second delay, when you get a HTTP 429 response: this may exacerbate the problem.
Please note these limits are subject to change. Check this page regularly for the most up-to-date information.
If you have any questions or errors, please visit the Support (/support/contact) page for assistance.
