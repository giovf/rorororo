Set up agent
Shared payment tokens (SPTs) grant sellers scoped access to customers’ payment methods for agent-initiated purchases. SPTs are available to agents, customers, and sellers in the US, Canada, and select European countries.
View all supported countries
Sellers
Agents
Connect platforms
As the seller, you receive a shared payment token (SPT) (/api/shared-payment/granted-token) from the agent. An SPT is a scoped grant to use the customer’s payment method. The agent grants SPTs to your Stripe profile (/get-started/account/profile) , each with usage and expiration limits.
Before you begin
By using SPTs, you agree to the terms of service (https://stripe.com/legal/ssa-service-terms#stripe-agentic-commerce-seller-services-preview) .
If you don’t already have a Stripe account, create one (https://stripe.com/register) .
Create your Stripe profile (/get-started/account/profile) in the Dashboard.
Generate an SPT in a sandbox
In a sandbox, use the test helper to generate an SPT without an agent. The following request grants your account an SPT using a test payment method and simulates limits that agents might set, such as currency, maximum amount, and expiration window.

curl https://api.stripe.com/v1/test_helpers/shared_payment/granted_tokens \
-u " sk_test_... :" \
-H "Stripe-Version: 2026-09-30.preview" \
-d payment_method = pm_card_visa \
-d "usage_limits[currency] = usd " \
-d "usage_limits[max_amount] = 1000 " \
-d "usage_limits[expires_at] = 1798761600 "
Set usage limits
Use the usage_ limits parameter to specify the maximum amount and expiration window. The agent sets the maximum amount to match the total amount of the transaction.
Specify the payment method
Use the payment_ method parameter to specify the payment method the customer selected for the purchase.
Test your live mode integration
To test your integration in live mode, use the link-cli (https://docs.link.com/quickstart/overview) to issue SPTs from your personal Link account. The link-cli can provision one-time shared payment token credentials. Follow the instructions in the quickstart (https://docs.link.com/quickstart/agents) to install the link-cli skills or register it as an MCP server in your preferred agent.
Log in to your personal Link account, or sign up (https://app.link.com) if you don’t have one.
Command Line
npx @stripe/link-cli auth login
Choose the payment method you want to use. If you don’t already have one, add a payment method (https://app.link.com/wallet) .
Command Line
npx @stripe/link-cli payment-methods list
Create a spend request to issue a one-time SPT scoped to your Stripe profile. The --amount value is in the currency’s smallest unit (for example, 100 is 1.00 USD).
Command Line
npx @stripe/link-cli spend-request create \
--payment-method-id csmrpd_xxx \
--context "Test purchase to confirm that my business can accept a one-time shared payment token issued by link-cli in live mode" \
--amount 100 \
--credential-type shared_payment_token \
--network-id profile_xxx \
--request-approval
Use a shared payment token
After you receive a granted SharedPaymentToken , you can process the payment with Stripe or use the SPT with a third-party processor (#resolve) . To process the payment with Stripe, create a PaymentIntent .
The following example uses a non-recurring SPT to make a payment.

-u " sk_test_... :" \
-H "Stripe-Version: 2026-09-30.preview" \
-d amount = 1000 \
-d currency = usd \
-d "payment_method_data[shared_payment_granted_token] = spt_123 " \
-d confirm = true
To make recurring charges, reuse the SPT directly in each PaymentIntent . The SPT must have usage_ limits. recurring_ interval set. Stripe rejects setup_ future_ usage and payment_ method_ options[card][setup_ future_ usage] when you create or confirm a PaymentIntent with an SPT, including a recurring SPT. Stripe validates off_ session separately against the SPT’s permissions.

When you confirm a PaymentIntent with the SPT, Stripe sets payment_ method to a new PaymentMethod cloned from the customer’s original payment method. Subsequent events, such as refunds and reporting, behave as if you provided the PaymentMethod directly.

Stripe returns a credential type based on your account’s credential configuration and the payment method backing the SPT.
Security tip
In collaboration with the card networks, Stripe might use tokens issued through network programs such as Mastercard’s Agent Pay, Visa’s Intelligent Commerce, and American Express ACE Kit on your behalf. Stripe submits the requested data to the card networks to provision and process those tokens for related transactions.
Record a payment
After you capture the payment with your processor, record a payment (/api/payment-record/report) and confirm the checkout flow.
Command Line
cURL
curl https://api.stripe.com/v1/payment_records/report_payment \
-u " sk_test_... :" \
-d "payment_method_details[shared_payment_granted_token] = spt_123 " \
-d "amount_requested[value] = 1000 " \
-d "amount_requested[currency] = usd " \
-d initiated_at = 1782172800 \
-d outcome = guaranteed \
-d "guaranteed[amount][value] = 1000 " \
-d "guaranteed[amount][currency] = usd " \
-d "guaranteed[final_capture] = true " \
-d "guaranteed[guaranteed_at] = 1782172800 " \
-d "processor_details[type] = custom " \
-d "processor_details[custom][payment_reference] = auth_order_id_1 "
Configure resolution behavior
Because the SPT Resolve API handles sensitive data, Stripe configures its behavior for your account. The configuration determines:
Encryption : Whether Stripe encrypts each credential type.
Encrypted fields : Which fields Stripe encrypts for each credential type.
The API returns encrypted fields in the encrypted property for the credential type. Encryption works as follows:
encryption_ type : The method Stripe used to encrypt the data. This value matches your credential configuration.
encryption_ block : The encrypted credential data.
encryption_ block_ fields : The layout of the data in encryption_ block . Each comma-separated entry uses the format <field_ name>:<start_ index>:<length> .
key_ id : The identifier for the encryption key.
You can only resolve an SPT one time.
Handle errors
The API returns a 400 error in the following cases:
Stripe hasn’t created a credential configuration for your account
You previously resolved the SPT
You previously used the SPT in a PaymentIntent
Stripe can’t resolve the payment method into a usable credential
Meet PCI requirements
If you haven’t provided Stripe with your PCI Attestation of Compliance, Stripe must encrypt credentials that fall within PCI scope. Stripe encrypts these credentials with a public key whose corresponding private key you can’t access. For example, Stripe can use a public key owned by your payment processor.
If you’re PCI compliant, you must provide Stripe with your PCI Attestation of Compliance (https://stripe.com/en-ca/guides/pci-compliance) .
Listen for webhook events
We send events to you and the agent when:
You use a granted SPT to accept a payment.
You resolve a granted SPT for use with a third-party processor.
The agent revokes a granted SPT. You can’t create a payment with a revoked SPT.
Verify webhook signatures to confirm that events come from Stripe. Learn how to verify events (/webhooks#verify-events) .
Event	Description	Use case
shared_ payment. granted_ token. deactivated	The SPT has been deactivated (consumed, resolved, expired, or revoked).	Listen for this event to know when you can no longer use the SPT.
