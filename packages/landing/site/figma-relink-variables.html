Figma variables broken after moving a file? Relink them to the library by name.

It happens the same way every time. A file is copied to another team or account, a design system library is swapped for a newer one, or a collection is published and then renamed, and suddenly every fill, stroke, padding and radius points at a local copy of the variable, or at a library variable that no longer exists. Figma's "swap library" moves component instances, but the plain frames and layers on the page stay on the old variables, and the forum threads asking how to fix that get the same answer: do it by hand, or find a plugin. Variables Toolkit's Relink tab is that plugin: it finds every layer bound to a local or unpublished variable and moves it onto the enabled library's variable with the same name and type, in one click.

What actually breaks, and why "swap library" does not fix it

  • Copying a file out of a team. Variables are owned by the file that published them. In the new team the library is not enabled, so Figma keeps the bindings as references to variables the file can no longer resolve: the values still render, but nothing updates and the variable picker shows them as detached or local.
  • Swapping or republishing a library. "Swap library" rewires component instances. Frames, text and shapes drawn on the page keep their old variable ids, which is why a page looks right until the old library is unpublished and then goes grey.
  • Renaming a collection, or duplicating it locally. A local collection with the same variable names is a different set of ids. Every layer bound to it has to be rebound before the library can be the single source of truth again.

Figma's quick action Detach deleted variables only removes bindings to variables that were deleted; it does not point them at anything. Relinking means finding the matching library variable for each binding and rebinding it, layer by layer.

How Relink works

  1. Enable the library in the file (Assets → Libraries). Relink reads the enabled libraries' variables through Figma's team-library API; it never sees other files.
  2. Open Variables Toolkit, pick the Relink tab, and choose the selection or the whole page. The scan runs in chunks with a live count and a Cancel button, so a large page never freezes Figma.
  3. Review the plan: each group names the local or unpublished variable, the library variable it will move to, and how many layers that touches. A name that two enabled libraries both publish waits until you pick the collection.
  4. Click Relink. Layers already bound to the library are left alone, so running it twice is harmless.

Honest limits

  • Relink moves solid fills and strokes, and the number properties Link binds: padding, gaps, corner radii and sizes. Text, effect, stroke-weight and variable-alias bindings are not moved yet.
  • Matching is by trimmed name and resolved type, one library at a time. A variable whose name changed in the library is listed as unmatched, not guessed.
  • Only the open file. Figma's plugin API cannot reach other files, so a library used across a workspace is relinked file by file.
